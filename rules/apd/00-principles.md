# APD基本原則

## 原則

- **人間の時間とAIの時間を分離する。** Intent / Spec フェーズは人間の時間（対話的）、Build は AI の時間（自律実行）
- **AI フェーズの途中で人間の介入をゼロにする。** 人間は最初に意図を決めたら手を離す。Build は auto mode で `/goal` を走らせる（`01-phases.md`）
- **ドキュメントは生きた 1 枚として編集し続ける。** 差分を別ファイルで積まない。履歴は git が正史として持つ
- **人間の確認面は GitHub（PR + issue）。** `docs/apd/` は AI の作業材料であって、人間が日常的にスキャンする場所ではない
- **判断に迷ったら自己判断せずリーダーエージェント（AI）に聞く。** 人間への問い合わせではない。聞きすぎるほうが暴走するより安全
- **薄い規約レイヤに留める。** APD が持つのは Design / Spec / Decision の規約と最小限のスキルだけ。ループ・並列化・タスク管理・GitHub 連携は Claude Code 本体の機能（`/goal`, subagent, agent teams, dynamic workflows, hooks, Task ツール）に委譲する
- **APD はユーザーの CLAUDE.md を書き換えない。** APD の規約は `.claude/rules/apd/`（自動ロード）に置く。CLAUDE.md に使用宣言・バージョンを書き込まない（腐る・二重管理になる）。CLAUDE.md はプロジェクト固有のことだけ

## 判断の優先順位（Build 中）

1. **CLAUDE.md に明記されている** → それに従う
2. **CLAUDE.md に書かれていない** → リーダーエージェントに判断を仰ぐ
3. **リーダーエージェントが判断できない** → Spec に先出しするか、完成後の実機確認で人間に確認し次サイクルで Spec を修正する

頻出の判断は CLAUDE.md に昇格させて自律範囲を広げていく。
