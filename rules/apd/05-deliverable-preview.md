# APD 成果物プレビュー（任意）

実装前に「何ができるか」を可視化し、方向性のズレを早期に検出する手段。**任意**であり、UI が複雑・関係者との認識合わせが要る・アーキテクチャが入り組んでいる、といった「先に見せた方が手戻りを防げる」ケースでのみ作る。Spec フェーズではテキストで完成像の方向性を合意し、Build フェーズでは必要なら実装開始前に図・モックを生成する。

## プレビュー対象（必要なものだけ）

| 種別 | フォーマット |
|------|------------|
| アーキテクチャ図 / シーケンス図 / データモデル（ER 図）/ 画面遷移図（stateDiagram） | Mermaid |
| UI モック | 静的 HTML + CSS |
| API 仕様（エンドポイント、リクエスト/レスポンス例） | Markdown |

## 配置

作る場合のみ `docs/apd/preview-{feature}/` を追加する（`architecture.md`・`screens/{screen-name}.html`・`api-spec.md` 等）。プレビューが 1 つだけなら `docs/apd/preview-{feature}.md` 単一ファイルでよい。

人間は PR 本文の「試し方」と合わせて、必要に応じてプレビューを目視する。期待と大きく外れていれば次サイクルで Spec を編集して方向修正する。
